## 2. 批处理要解决什么

用户想一次交给 Aletheia 一批同样的活，比如：

- “把这 50 个 Markdown 每个都总结成三句话”；
- “对这份问题清单逐条从知识库回答”。

现在只能一条条手动问，或者自己写脚本循环调用命令行。后者每条都要重新启动工具服务，而且中断后不知道哪些跑过了。

批处理要做到：

- 读一个清单，逐项运行；
- 输出一个结果文件，每项写状态、答案和用量；
- 中断后再跑，只跑剩下的；
- 某一项失败不影响别的项；
- 有总预算，用完就停。

## 3. 现状（已核实）

- **单次任务的命令行**：`python -m app.agent "<目标>"` 已经有这些：
  - `--result-json`：写结构化结果（`app/agent/__main__.py:254` 的 `write_result`）；
  - `--output-schema`：输出契约（D-093）；
  - `--max-tokens` / `--max-seconds`：本次任务的预算，用 `RunMeter` 套在任务外面（`__main__.py:708-709`）。
- **一个服务跑多个任务**：交互模式就是一个 `RagAgentService` 跑很多轮（`__main__.py` 的 `interactive`），工具服务按运行启动，服务实例可以复用。
- **评测的骨架**：`bench/run_bench.py` 的 `run_one` 每题起一个子进程，太重，批处理不照搬，只借它的结果汇总思路。
- **请求去重**：`query_result(request_id=...)` 会回放已有结果（`rag_agent_service.py` 的 `_replay`），但要开着对话归档才有效。批处理不依赖它，改用结果文件本身判断哪些做过了（见 4.3）。
- **追问**：单一循环的 `ask_user` 会让任务阻塞。执行器有 `allow_ask_user=False` 这个选项（`app/agent/agent_loop.py:230`），团队成员就用它，但服务层现在没有对外暴露。
- **没人看着时的确认**：权限规则的“问”（D-094）、用户 MCP 的 `external` 工具（D-095），在不是终端时都按拒绝处理；项目说明（D-096）不是终端时不问，按没确认处理。批处理沿用这些，不用另做。

## 4. 设计

### 4.1 入口和清单

- 新入口：`python -m app.agent.batch 清单.jsonl --out 结果.jsonl`。
- 清单每行一个 JSON 对象：
  - `id`：必填，字符串，整个清单里唯一，最长 100 字符；
  - `goal`：必填，这一项的目标；
  - `output_schema`：可选，覆盖整批的 Schema。
- 另一种写法（第 8 节第 1 问）：`--each-file "docs/*.md" --goal "用三句话总结 {file}"`，宿主展开成清单。`{file}` 换成相对工作目录的路径，`id` 就是这个路径。
  - 文件只在工作目录里找；
  - 禁止目录里的跳过；
  - 最多 500 项。
- 整批共用的选项和单次任务一样：
  - `--filesystem-root`、`--no-knowledge`、`--execution-mode`（只收 `single`，第 8 节第 4 问）；
  - `--output-schema`、`--persona`；
  - `--trust-instructions` / `--no-instructions`；
  - `--confirm-system-drive`、`--confirm-mcp`。
- **只读**：第一版不收 `--write-root`、`--sandbox`（第 8 节第 2 问）。每项都按只读任务跑，看不到写入和运行类工具。

### 4.2 逐项运行

- 整批只开一个 `RagAgentService`。每项用一个新会话 `batch-<批次编号>-<序号>`，项与项之间不共享会话历史。
- 批次编号是清单内容的 SHA-256 前 12 位；清单一改，批次编号就变。
- 每项不能追问：给服务加一个只对这次请求生效的 `allow_ask_user=False`，传到单一循环的执行器（第 8 节第 3 问）。模型缺信息时在答案里说明缺什么。
- 默认一项一项按顺序跑，不并发（第 8 节第 5 问）。
- 每项的预算：`--item-max-tokens`（默认 200,000 令牌）、`--item-max-seconds`（默认 300 秒）。整批的预算：`--max-tokens`（**必填**，无人值守不允许不设上限）、`--max-seconds`（可选）。
- 整批预算用完后，正在跑的那项照常按失败处理，剩下的项标 `not_run`，不再调用模型。
- Ctrl+C：正在跑的那项记成 `cancelled`，结果文件写完整后退出，退出码 130。

### 4.3 结果文件和续跑

- `--out` 是 JSON Lines，每项一行，跑完一项就追加一行并刷新到磁盘。每行包括：
  - `id`、`status`（`completed`、`failed`、`blocked`、`cancelled`、`not_run`）、`failure_kind`；
  - `answer`（最终答案原文）、`output`（有 Schema 时解析出的对象）；
  - `tokens`、`seconds`、`task_id`；
  - 批次编号。
- 第一行是批次头：批次编号、清单路径、开始时间、选项（不含路径以外的敏感信息）。
- **续跑**：`--out` 已存在时：
  - 先读出来，批次编号必须和这次一致，否则报错退出，不覆盖；
  - `completed` 的项跳过，其余的重跑（`failed`、`cancelled`、`not_run` 都重跑）；
  - 重跑的结果追加一行，读结果时同一个 `id` 以最后一行为准。
  - 加 `--skip-failed` 时，`failed` 的项也跳过。
- 结果文件里有答案原文，只写到用户指定的位置；不进轨迹、钩子事件、审计和日志（D-059）。终端只打印每项一行：序号、`id`、状态、令牌数。
- 结束时打印汇总：各状态的项数、总令牌、总时间。退出码：全部 `completed` 为 0；有失败为 1；整批预算用完、还有 `not_run` 为 2。

## 5. 测试（离线，用假模型）

- 清单解析：缺 `id`、`id` 重复、空 `goal`、不是 JSON 的行，报中文错误并指出行号。
- `--each-file`：
  - 只展开工作目录里的文件；
  - 禁止目录里的跳过；
  - 超过 500 项报错；
  - 和清单文件不能同时给。
- 逐项运行：
  - 三项里第二项失败，第一项和第三项照常完成；
  - 每项一个新会话，第二项的请求里没有第一项的内容；
  - 写入工具对每项都不可见。
- 不能追问：模型调用 `ask_user` 时，工具列表里根本没有它；其他入口的默认行为不变。
- 预算：
  - 单项超预算时这一项 `failed`（`budget`），下一项照常；
  - 整批预算用完后剩下的都是 `not_run`，不再调用模型；
  - 不给 `--max-tokens` 时参数错误。
- 续跑：
  - 中断后再跑，只跑没完成的；
  - 清单改了，批次编号对不上，报错并且不碰结果文件；
  - 同一个 `id` 多行时取最后一行。
- 输出契约：有 Schema 时 `output` 是解析后的对象；不合格的项 `failed`（`contract`）。
- 记录：答案原文不进轨迹和钩子事件。
- 没用批处理时，其他入口的请求和事件逐字不变，黄金对照文件不变。

## 7. 风险

- **花费**：一批几十项，每项都是一次完整任务，花费可能很大。所以整批 `--max-tokens` 必填，开头打印项数和预算上限，要求在终端输入 `y`；不是终端时要加 `--confirm-batch`。
- **结果文件损坏**：每行单独追加，最后一行写到一半时读的时候忽略并提示，那一项会重跑。
- **没用真实模型验证**：测试全用假模型。真实跑一小批要另外征得用户同意。

## 8. 要用户定的

1. **怎么给一批**：推荐**清单文件和 `--each-file` 两种都做**。另一个做法是只做清单文件，文件那种由用户自己生成清单。
2. **读写**：推荐**第一版只读**。另一个做法是允许 `--write-root`，但批量写文件的风险大，出错很难一项项核对。
3. **追问**：推荐**每项都不能追问**，加一个只对单次请求生效的 `allow_ask_user=False`。另一个做法是追问的项记成 `blocked` 跳过，但那样模型可能本可以自己说明缺什么。
4. **执行方式**：推荐**只用单一循环**。团队模式一项就花很多令牌，批量不划算。
5. **并发**：推荐**按顺序一项一项跑**。并发更快，但会和预算、模型服务商的限流互相干扰，以后再加。
6. **整批预算**：推荐**`--max-tokens` 必填，并在开头确认一次**（`--confirm-batch` 用于不能交互时）。另一个做法是像单次任务一样默认不限，但无人值守时风险太大。
7. **记录**：推荐新开 **D-097**。
