## 1. 要解决的问题

常用的任务每次都要把要求写一遍：审查时要按位置、严重程度列出来，不许改文件；补测试时要沿用已有写法、跑通为止。写漏了，结果就不稳定。

个人命令把这些要求存成模板：输入 `/review app/api`，宿主把模板和参数拼好，作为一个普通任务交给智能体，并按模板固定执行模式和读写权限。

和人设的关系：命令属于人设。人设的指令管“怎么讲”（学习习惯、讲解风格），命令管“做什么”（这次任务的目标、步骤和输出格式）。同一个 `/explain`，在“学 agent”里可以写成先讲概念和取舍，在“学后端”里写成先看代码再点评。

## 2. 命令是什么

每个命令一个文件，开头是 `+++` 包起来的 TOML 设置，下面的正文是模板，格式和人设文件一样：

```
+++
description = "只读审查代码，按位置和严重程度列出问题"
usage = "/review 路径"
args = "required"
mode = "single"
write = false
+++
审查 {{args}}。
……
```

| 键 | 含义 | 取值 |
| --- | --- | --- |
| `description` | 列表里显示的一句话，最多 60 字 | 必填 |
| `usage` | 用法提示，参数不对时显示 | 可选，默认 `/名字 参数` |
| `args` | 参数要求 | `required`（必须给）、`optional`、`none`（不收参数） |
| `mode` | 执行模式 | `single` 或 `team`；不写表示不固定 |
| `write` | 读写 | `false` 强制只读；`true` 表示要改文件；不写表示不管 |

- 不认识的键报错。不放 `use_memory`、`workspace`：这两项由人设的默认设置管。
- 正文最多 4000 字，文件最多 64 KB。`{{args}}` 换成命令后面的全部文字；`args = "optional"` 而没给参数时换成“（未指定）”。正文里没有 `{{args}}` 时，参数接在正文后面另起一行。
- 名字：小写字母开头，只能有小写字母、数字和 `-`，最多 20 个字符。不能和现有命令重名：`help`、`new`、`exit`、`quit`、`dir`、`remember`、`memories`、`forget`、`persona`、`btw`，以及新加的 `commands`。
- 每个人设最多 30 个命令。
- 模板只是文字和选项，不含代码，不动态加载任何模块（D-058）。

## 3. 存在哪

- 放在人设目录下，不加新的配置项：`data/personas/<用户目录>/commands/<人设编号>/<命令名>.md`。
  - 命令名只有小写字母、数字和 `-`，可以直接当文件名；
  - 人设功能关闭（`PERSONAS_DIR` 留空）时，个人命令也一起关闭；
  - 人设目录已经是受保护目录、已经在 `.gitignore` 里，评测子进程和 `tests/conftest.py` 已经把它设成空，这些都不用另外处理；
  - 写入原子替换，用人设那把锁；
  - 每次用命令时重新读文件，用户在编辑器里改完立刻生效。
- **预置命令**：六个模板放在仓库里（`app/services/command_presets/*.md`）。一个人设第一次用到命令功能时（列出、运行、编辑都算），把六个模板复制进它的目录，`state.json` 里记下这个人设已经复制过。
  - 之后这些文件完全归这个人设：可以改、可以删，删了不会再自动出现；
  - `/commands reset 名字` 把一个预置命令恢复成仓库里的版本；
  - 仓库以后改进了预置模板，已经复制过的不会自动更新，要自己 `reset`。
- **新人设**：和“默认”一样，从六个预置命令开始（第一次用到时复制）。
- **删除人设**：它的命令目录一起删掉。人设的删除确认里写上“它的 N 个命令也会删除”。

## 4. 命令怎么变成任务

### 4.1 入口

- 命令行和网页把整行输入原样作为 `question`，另外带上命令名，调 `query_result(..., command='review')`。
- 服务先定下这个任务的人设（会话绑定的，或者这次请求指定的），再从**这个人设的命令**里找，读文件、检查参数、拼模板。找不到就不开始任务，提示“「学后端」里没有 /review 这个命令”。
- 对话里记的是**用户输入的那一行** `/review app/api`，拼好的模板作为这个任务的约束加进去：
  - 对话气泡、历史、按 `request_id` 重放时比对的都是用户原话，不会冒出一大段模板；
  - 约束前面加一句宿主写的英文：`The user ran the personal command /review with the arguments below. What the command asks for, written by the user; it is the request for this task:`，后面接拼好的正文；
  - 和人设指令一样走 `task.add_constraint`，系统提示不改，团队成员和调研成员也看得到；人设指令在前，命令在后，两者冲突时以命令为准（命令是这一次的要求）。
- 阻塞后续跑（比如 `/quiz` 等你回答）时，约束和选项都是任务开始时定下的，不再重新读文件。
- 参数是 `required` 却没给，或者是 `none` 却给了，任务不开始，提示 `usage`。

### 4.2 执行模式和读写

| 来源 | 模式 | 读写 |
| --- | --- | --- |
| 命令 | 写了就以它为准，比这条消息的选择还优先 | `false`：强制只读；`true`：这次必须能写，否则不开始 |
| 这条消息的选择 | 命令没写时用 | 照旧 |
| 人设的默认 | 再往下 | 照旧 |
| 服务的默认 | 最后 | 照旧 |

- **命令只收紧，不放宽**：`write = true` 不会打开写入。这次是只读（不管是消息、人设还是服务定的）而命令要改文件时，任务不开始，提示“这个命令要改文件，现在是只读：网页上勾上‘可写’，或者把人设的默认设置改成可写”。
- **模式可以由命令固定**：模式不涉及权限，只关系命令能不能做成。比如 `/quiz` 要等你作答，团队模式的负责人不能问用户（`delegation.py:379` 的 `allow_ask_user=False`），所以 `/quiz` 必须是 single。
- 模式固定成 single 或 team 时不走路由模型（`run_assembler.py:111`），也就不会出现路由把 `/test` 误判成只读、藏掉写入工具的情况。
- 六个预置命令都写了 `mode = "single"`。

### 4.3 显示和记录

- 新任务开始时发一个 `command` 事件：命令名、模板字数、固定了哪几项（只有键名）。
- 命令行打印一行：“命令 /review：只读，single 循环。”网页在任务卡片的“执行过程”里显示同样的话。
- 轨迹、钩子事件和审计不记模板正文；`route` 事件照旧记下最终的选项。

## 5. 预置的六个命令

都是 `mode = "single"`。正文是用户可以改的中文，实施时按下面写进 `command_presets/`。

### `/explain 路径或问题`（只读，必须给参数）

```
讲清楚：{{args}}
- 如果是代码路径，先读代码再讲；如果是概念，结合这个项目里用到它的地方讲，项目里没有就直接讲。
- 先用两三句话给结论，再分步讲它怎么工作、为什么这样设计。
- 最后列出关键的文件和行号，方便我自己去看。
- 不要改任何文件。
```

### `/quiz 主题`（只读，必须给参数）

```
围绕「{{args}}」出 5 道题考我。
- 考理解，不考死记；由浅到深，至少一道结合实际代码或场景。
- 把 5 道题一次问完，然后停下来等我回答，不要先给答案。
- 收到回答后逐题批改：对的说为什么对，错的讲清错在哪、正确答案是什么。
- 最后指出我最薄弱的一点，建议接下来看什么。
```

### `/note 主题`（可写，参数可选）

```
把这次会话里关于「{{args}}」的内容整理成一篇学习笔记；没指定主题就整理整个会话。
- 写到工作目录下的 notes/ 里，文件名用主题和日期；已有同名文件就在末尾追加，不覆盖。
- 结构：要点、关键概念和例子、我容易错的地方、还没弄懂的问题。
- 只写会话里确实讲过的内容，不要补没讲过的。
- 写完告诉我文件路径。
```

### `/review 路径`（只读，必须给参数）

```
审查 {{args}}。
- 先读代码再下结论。只报真正的问题：会出错的逻辑、漏掉的边界情况、安全风险、明显的性能问题；不报个人风格偏好。
- 每个问题写：位置（文件和行号）、严重程度（高、中、低）、为什么是问题、怎么改。
- 按严重程度从高到低排；没发现问题就直接说没有。
- 不要改任何文件。
```

### `/test 路径`（可写，必须给参数）

```
给 {{args}} 补测试。
- 先读代码和项目里已有的测试，沿用同样的测试框架和写法。
- 覆盖正常情况、边界情况和出错的情况；不写重复凑数的测试。
- 能运行就运行，直到跑通；如果发现是被测代码的 bug，不要改被测代码，告诉我。
- 没有运行工具时只写测试，并明确说明没有运行。
- 最后列出新增了哪些测试和运行结果。
```

### `/fix 问题描述`（可写，必须给参数）

```
修复这个问题：{{args}}
- 先找到原因，确认了再改；找不到原因就停下来告诉我查到了什么，不要猜着改。
- 改动尽量小，只改和这个问题有关的地方。
- 能运行测试就运行，确认修好了、没有弄坏别的。
- 最后说明原因是什么、改了哪些文件、为什么这样改。
```

- `/note` 依赖会话历史：任务开始时宿主已经把会话历史放进上下文（`_prepare_task`），不用另外处理。
- `/test` 的运行靠沙箱工具；服务没开沙箱时智能体看不到运行工具，按模板只写测试并说明。

## 6. 管理命令

所有管理命令都作用在**当前会话的人设**上。

### 6.1 命令行（`app/agent/__main__.py`）

| 命令 | 作用 |
| --- | --- |
| `/名字 参数` | 运行当前人设的一个命令 |
| `/commands` | 列出当前人设的命令：名字、说明、只读还是会改文件；第一行写明是哪个人设的 |
| `/commands show 名字` | 显示模板正文（带行号）、设置和文件位置 |
| `/commands new 名字` | 按骨架新建一个命令文件，打印路径，用编辑器去写 |
| `/commands delete 名字` | 删除；要输入 y 确认，预置命令删了可以用 `reset` 找回 |
| `/commands reset 名字` | 把预置命令恢复成仓库里的版本，只对六个预置名字有效 |

- 交互循环里，先认现有命令，再查当前人设的命令，都不是才报“未知命令”。
- 有任务在等回答时不运行个人命令，提示“有任务在等你回答：直接回答，或者 /new 放弃它”。
- 单次任务（命令行带目标）也认：`python -m app.agent "/review app/api"`；带 `--persona` 时用那个人设的命令。
- 人设功能关闭时回一句“个人命令要先开启个性化人设”。`INTERACTIVE_HELP` 同步更新。

### 6.2 网页（`app/api/app.py`、`app/api/static/`）

- 接口都受访问令牌保护，请求体有大小上限，挂在人设下面：
  - `GET /api/personas/{id}/commands`：列表（名字、说明、用法、参数要求、模式、读写）；
  - `GET /api/personas/{id}/commands/{name}`：完整内容，含模板正文；
  - `POST /api/personas/{id}/commands`：新建；`PUT .../{name}`：改；`DELETE .../{name}`；
  - `POST .../{name}/reset`：恢复预置命令；
  - `POST /api/sessions/{id}/messages`（`app.py:322`）的请求体加 `command` 字段。
- 输入框：
  - 输入 `/` 时在输入框上方弹出当前人设的命令列表（名字和说明），继续输入会筛选，点一下或按 Tab 补全；切换人设后列表跟着换；
  - 提交时，`/persona`、`/btw` 照旧由页面处理；是当前人设的命令的，带上 `command` 发出去；
  - 不是任何命令的 `/xxx`：补全框里没有匹配项就是提示，回车照常当普通消息发出去，和现在一样。
- 顶栏加“命令”面板，样子和人设面板一样：上面一个下拉框选命令，下面编辑说明、用法、参数要求、模式、读写和模板正文，按钮有保存、新建、删除、恢复预置。面板标题写明是哪个人设的命令。模板正文按纯文本显示。

## 7. 分步

一次做完，一个提交：命令文件和服务层、命令行、网页。改动面和人设第一步差不多。

### 7.1 测试

- `tests/test_commands.py`（新建，只用临时目录）：
  - 解析：认识的键、不认识的键报错、格式坏了报错、正文超过 4000 字报错、名字不合规或和现有命令重名被拒、一个人设超过 30 个被拒；
  - 拼模板：`{{args}}` 替换、可选参数没给时的“（未指定）”、正文没有 `{{args}}` 时接在后面、参数要求不满足时不开始；
  - 跟着人设走：两个人设各改自己的 `/explain` 互不影响；新人设从六个预置命令开始；删除人设时命令目录一起删；
  - 预置命令：第一次用时复制、删了不再出现、`reset` 恢复、`reset` 非预置名字被拒；
  - 人设功能关闭时个人命令也关闭。
- 服务层：
  - 模型收到的第一条请求的 `constraints` 里有拼好的命令，开头是宿主那句话；人设指令在它前面；
  - 用的是这个任务的人设的命令，请求指定了别的人设时用那个人设的；
  - 对话里记的是用户原话；同一个 `request_id` 重放不冲突；
  - `write = false` 时写入和运行工具不出现；`write = true` 而这次只读时任务不开始；
  - `mode` 固定时不调路由模型，而且压过这条消息的选择；
  - 阻塞后续跑不重复加约束，续跑时改了命令文件也不变；
  - 轨迹、钩子事件、审计里没有模板正文。
- 命令行：运行、`/commands` 各子命令的输出、等回答时被拒、单次任务带命令和 `--persona`、功能关闭时的提示。
- 网页：各接口的令牌、请求体大小、名字检查；`app.js` 通过 `node --check`；用假模型在本机起服务看补全列表、切换人设后列表变化、命令面板和任务卡片。
- 六个预置模板各有一条测试：能解析，设置和第 5 节一致。
- `init.ps1` 必须通过。

## 11. 实现时的补充

- **复制过没有看目录在不在**：方案说在 `state.json` 里记下哪个人设复制过预置命令。实现时改成看这个人设的命令目录在不在：目录不在就复制，在了（哪怕删空了）就不再复制。不用改 `state.json` 的读写，删人设时删掉目录也就忘了这件事。
- **数命令不会触发复制**：删除人设时数它有几个命令（`CommandBook.count`），没用过命令的人设是 0，不会为了数一下先复制六个文件。
- **`query_result` 的长度守卫**：`tests/test_run_assembler.py` 要求它不超过 80 行。人设和命令的选择挪进了新方法 `_persona_choices`，顺序照方案：命令先定模式和只读，人设的默认再填剩下的，最后检查要写的命令是不是碰上了只读。
- **“要写”只看选项**：`write = true` 的命令只在这次的写入选项是关时拒绝。命令行没给 `--write-root` 时选项是开的，但其实没有写入工具，这时命令照样开始，由智能体说明写不了。要做得更准，得让服务知道写入工具在不在，这次没做。
- **`CommandError` 是 `PersonaError` 的子类**：命令行和网页原来接人设错误的地方都能接住；网页的错误码前缀是 `command_`。
- **网页补全**：输入框里只有 `/` 加名字的一部分时弹出列表；上下键选，Tab 补全；回车时如果还没打完名字就补全，打完了就发送。没有匹配的命令时列表不出现，回车照常当普通消息发出去。有任务在等回答时输入命令，页面提示先回答，不发送。
- **命令不能改名**：网页接口拒绝改名，要改就新建一个再删掉旧的。
- **`/commands delete` 要输入 y**；网页删除前也确认。删人设时，命令行和网页的提示都写明它的命令有几个。
- 用假模型在本机起网页看过：输入 `/re` 弹出 `/review`，回车补全，发出后任务卡片写“命令 /review：只读，普通模式”；关掉写文件再发 `/fix` 被拒；`/reveiw x` 当普通消息发出；命令面板改模板、新建命令都正常；切到另一个人设后补全列表是它自己的；删人设的确认框写“它的 6 个命令会一起删除”。控制台没有报错。
- 没有用真实模型验证。黄金对照文件一个都没变。
