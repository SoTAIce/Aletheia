# 选择工作目录：修改方案

日期：2026-11-10。状态：**已实现，在实验分支** `exp/workspace-choice`（workspace-001，D-074），未并入 `main`。用户的回答和对前文的修订见第 10 节，实现以第 10、11 节为准。

## 1. 背景

用户 2026-11-09 提出：希望在智能体里可以选择工作目录；选的目录涉及 C 盘时，要给用户弹警告。

现状（HEAD `db13d64`）：

- 目录只能在**启动时**定：命令行和网页后端都用 `--filesystem-root`（读）和 `--write-root`（写），或者 `.env` 里的 `MCP_FILESYSTEM_ROOT`、`MCP_FILESYSTEM_WRITE_ROOT`。换目录要重启。
- `tool_loader.local_mcp_servers()` 用这两个目录生成文件服务（`app.tools.filesystem.server`）和沙盒服务（工作区就是写目录）的启动参数。`RagAgentService` 在构造时收下这组参数（`self._mcp_servers`），**每次运行**都用它重新启动工具服务（`open_tool_registry`）。所以按次换目录在技术上不难，难在安全边界。
- 团队能力（`team_options_for`）、沙盒检查（`sandbox_problem`）、步骤时限（`step_timeout_for`）都在启动时按写目录算一次。
- 文件工具已有的保护（D-029）：密钥文件和目录不可读、不可列、不可写；会自动执行的位置不可写；路径不能跳出根目录（包括符号链接）。这些按根目录相对路径判断，换目录后照样生效。
- **D-051 明确否决过**“允许网页临时打开写入目录或沙盒（写入范围只应由启动参数决定）”。本功能会改变这条决定，需要用户确认（第 9 节问题 1），并记为新决定 D-074。

## 2. 这次做什么

**第一阶段（workspace-001）**：

1. 一个“工作目录”同时是读目录和写目录。写不写仍由每条消息的“写文件”开关决定（D-051 不变）。
2. 网页：会话顶部显示当前工作目录，可以输入路径更换；在系统盘（通常是 C 盘）时弹出确认框，确认后才生效。服务端同样检查，前端绕不过去。
3. 命令行交互模式：新增 `/dir` 命令查看和更换目录，系统盘时要求输入 `y` 确认。
4. 宿主固定的拒绝名单：磁盘根目录、系统目录、本项目的数据目录等，选了直接拒绝（第 4.1 节）。
5. 默认关闭：启动时加 `--choose-workspace` 才开启；可以用 `WORKSPACE_ALLOWED_ROOTS` 限定只能在哪些目录下选。

**不在这次范围内**：

- 网页上的目录浏览器（列出子目录点选）。浏览器拿不到本地文件夹的绝对路径，要做就得让服务端列目录，等于新开一个读文件系统的接口，留到以后。
- 读目录和写目录分开选（现在的启动参数仍然支持分开，这次不加到选择功能里）。
- 一个任务进行中途换目录：任务开始时定下，阻塞后恢复也沿用（同 D-051 的其他选项）。

## 3. 名词

- **工作目录**：一次运行里文件工具的根目录。写文件开启时也是写目录和沙盒工作区。
- **系统盘**：环境变量 `SystemDrive` 指向的盘（没有时按 `C:`）。只在 Windows 上判断；其他系统不弹警告。
- **系统盘确认**：用户明确同意在系统盘上的某个目录工作。只对那一个目录（规范化后的绝对路径）有效。

## 4. 设计

### 4.1 新文件 `app/services/workspace.py`（纯判断，不启动任何服务）

```python
@dataclass(frozen=True)
class WorkspaceCheck:
    path: str | None          # 规范化后的绝对路径（resolve 之后）；被拒绝时为 None
    system_drive: bool        # 在系统盘上，需要确认
    problem: str | None       # 拒绝原因的代码，见下表
    message: str | None       # 给用户看的中文说明

def check_workspace(raw: str, *, allowed_roots=(), protected=()) -> WorkspaceCheck: ...
def system_drive() -> str | None: ...
```

判断顺序（任何一条不过就拒绝）：

| 代码 | 条件 |
| --- | --- |
| `invalid` | 空、超过 500 字符、含空字节、不是绝对路径 |
| `not_found` | 不存在或不是目录 |
| `network` | UNC 网络路径（`\\server\share`），包括 `\\?\UNC\` 形式 |
| `drive_root` | 磁盘根目录本身（`C:\`、`D:\`），以及 POSIX 的 `/` |
| `system` | 位于 Windows 目录、`Program Files`、`Program Files (x86)`、`ProgramData` 之内，或就是用户主目录本身、`AppData` 及其以内 |
| `protected` | 与本项目的数据目录重叠：对话归档（`CONVERSATION_STORAGE_DIR`）、追踪目录、知识库数据、日志目录。**重叠**指“工作目录在它里面”或“它在工作目录里面”两种都算，否则智能体能读到别的会话的归档 |
| `not_allowed` | 配置了 `WORKSPACE_ALLOWED_ROOTS`，而目录不在其中任何一个之内 |

- 判断用 `Path.resolve(strict=True)` 之后的路径，**同时**检查用户输入的原路径：经由链接或目录联接（junction）指向系统盘的目录也算系统盘；原路径或解析后的路径任一落在拒绝名单里都拒绝。
- 系统盘本身不拒绝，只标 `system_drive=True`。
- 本项目自己的仓库目录不拒绝（读 README、解释代码是常见任务）；`.env` 等由 D-029 保护。

### 4.2 服务 `app/services/rag_agent_service.py`

1. 构造参数新增 `workspace_servers=None`：一个函数 `(root: str, writable: bool) -> tuple[StdioServerParameters, ...]`，由入口提供（内部调用 `local_mcp_servers`，带上 Tavily 和沙盒设置）。为 `None` 时功能关闭，行为和现在完全一样。
2. `query_result` 新增关键字参数 `workspace: str | None = None`、`workspace_confirmed: bool = False`：
   - 服务内部再调用一次 `check_workspace`（不信任调用方）。被拒绝时抛 `ValueError`（网页转成 400 `workspace_invalid`，带中文说明）；在系统盘而 `workspace_confirmed` 为假时抛专门的 `WorkspaceConfirmationRequired`（网页转成 409 `workspace_confirmation_required`）。
   - 规范化后的路径放进 `options['workspace']`，和模式、写入开关一起记在 `_task_options`；**恢复阻塞的任务时沿用任务开始时的目录**，忽略新传的值。
   - 用 `workspace_servers(path, options['write'])` 生成这次运行的工具服务，替代 `self._mcp_servers`。不给 `workspace` 时用启动时的目录。
3. 团队和沙盒：
   - 团队的工具名单按这次运行是否可写来算（现有 `_without_writes` 已经能收回写工具，沿用）。
   - 沙盒工作区跟着工作目录走。沙盒是否可用（Docker）只在启动时检查一次；换目录后如果目录不能挂载，沙盒工具会在调用时报错，不提前拦。
4. 同一个会话换了目录：下一次运行在固定上下文里加一条宿主说明“本会话的工作目录已更换，之前对话中提到的文件指的是原来的目录”。说明里**不写路径**，模型本来就只看到相对路径。
5. `run_options()` 增加 `workspace_available`、`default_workspace`、`allowed_roots`、`system_drive`。
6. 审计记录头（D-060）加 `workspace`（规范化路径），追踪面板上可以看到这次在哪个目录运行。这是用户自己的本机路径，只留在本机归档里。

### 4.3 网页

**接口**（`app/api/app.py`）：

- `POST /api/sessions/{id}/messages` 的 `options` 增加 `workspace: str | None`、`workspace_confirmed: bool | None`（`extra='forbid'` 的模型里新增字段）。同一 `request_id` 目录不同算冲突（沿用现有逻辑）。
- 新增 `POST /api/workspace/check`，请求体 `{path}`，返回 `{path, system_drive, problem, message}`，只做第 4.1 节的判断，不列目录内容、不透露目录里有什么文件。前端选目录时先调它，决定是否弹确认框。
- `/api/health` 的 `options` 带上第 4.2 节第 5 条的字段。
- 未开启功能时，传了 `workspace` 返回 400 `workspace_unavailable`。

**页面**（`app/api/static/`）：

- 会话标题下面一行“工作目录：`D:\proj\demo`  更换”；功能未开启时不显示。
- 点“更换”弹出一个小面板：输入框、最近用过的目录（本标签页保存，最多 5 个）、“使用”按钮。点“使用”先调 `/api/workspace/check`：
  - 被拒绝：在面板里显示原因，不更换。
  - 在系统盘：弹出确认框，标题“这个目录在系统盘（C:）上”，正文说明风险：开启写文件后智能体可以在这个目录里新建和覆盖文件、在沙盒里运行代码；系统盘上常有系统和程序文件，误改可能影响电脑使用；建议放到其他盘。两个按钮“仍然使用”和“取消”，默认焦点在“取消”。
  - 确认后把目录和“已确认”一起保存在这个会话的设置里，之后每条消息都带上。
- 目录按会话保存（`sessionStorage`，和现有的选项一样只在本标签页）；新建会话用默认目录。
- 回答阻塞的问题时，目录显示为不可更换，提示“回答问题时沿用原任务的设置”（和现有选项一致）。
- 写文件开关打开、且目录在系统盘时，开关旁边一直显示一个提醒图标。

### 4.4 命令行

- 交互模式新增 `/dir`：不带参数显示当前目录；`/dir 路径` 更换，系统盘时打印警告并要求输入 `y` 确认，其他输入都算取消。加进 `/help` 的说明。
- 用启动参数（`--filesystem-root`、`--write-root`）指定的目录在系统盘时：在标准错误输出打印一行中文警告，**不拦截**。理由是评测的临时目录就在 C 盘的 TEMP 下，拦截会让评测全部失败；启动参数是用户自己在命令行里写的，本身就是明确选择。
- 交互模式的 `/dir` 只在启动时给了 `--choose-workspace` 时可用，否则提示如何开启。

### 4.5 配置和开关

- 新开关 `--choose-workspace`（命令行交互模式和网页后端），或 `.env` 里 `WORKSPACE_CHOICE=true`。默认关闭。
- `WORKSPACE_ALLOWED_ROOTS`：分号分隔的目录列表；为空表示除拒绝名单外都可以选。
- 网页后端监听在非本机地址（不是 `127.0.0.1`、`localhost`）时，开启选择功能**必须**同时配置 `WORKSPACE_ALLOWED_ROOTS`，否则拒绝启动。理由：能连上网页的人都能把智能体指向这台电脑上的任意目录。
- 写文件仍要启动时开启写入能力：开启选择功能后，用 `--allow-writes` 表示“选中的目录可以写”，代替固定的 `--write-root`（两者同时给时，`--write-root` 作为默认目录）。没有写入能力时，选的目录只读。

## 5. 安全上的考虑

- **扩大了智能体能接触的范围**：以前只有启动时指定的一个目录，现在是本机大部分目录。拒绝名单、可选的白名单、非本机监听时强制白名单、默认关闭，是这次控制风险的四道手段。
- **系统盘确认在服务端校验**：前端弹框只是体验，服务端没有收到确认就返回 409，直接调接口绕不过去。
- **确认只对一个目录有效**：换到系统盘上的另一个目录要重新确认；目录被链接到别处也按解析后的路径重新判断。
- **不列目录**：检查接口只回答“能不能用、在不在系统盘”，不返回目录里的文件。
- **D-029 不变**：密钥文件、自动执行位置的保护按工作目录内的相对路径照样生效。
- **数据目录隔离**：对话归档、追踪、知识库数据与工作目录重叠时拒绝，防止读到别的会话。

## 10. 用户的回答和修订（2026-11-10，按此实现）

用户回答：1. 写入范围只由启动参数决定不太安全；2. 读写一般用同一目录，另外允许把文件拖进对话框给智能体读；3. 弹确认，只有用户确认才可以；4. 加一个强制不能读写的文件夹名单，其余自由度高一些；5. 先只输入路径，后续再改，现在处于测试阶段；6. 由 Claude 实现；7. 用工作树建实验分支，真正验证成功后再并入主分支。

修订（覆盖前面各节里不一致的地方）：

1. **所有目录走同一套检查，包括启动参数里的目录**（回答 1、3）。启动参数给的目录在系统盘上时也要确认：能交互就提示输入 `y`；不能交互（评测、脚本）必须带 `--confirm-system-drive`，否则拒绝启动。评测给子进程带上这个参数，因为它的临时目录是评测自己在 TEMP 里新建的。第 4.4 节“只警告不拦截”作废。
2. **选择功能默认开启**（不再需要 `--choose-workspace`），网页后端只在本机监听时开启；非本机监听时，只有配置了 `WORKSPACE_ALLOWED_ROOTS` 才开启。开启后网页的“写文件”开关可用，默认仍按启动时有没有写目录决定开或关。
3. **禁止读写的目录**（回答 4）：`.env` 里 `WORKSPACE_DENY_DIRS`（分号分隔）加上宿主固定的系统目录和本项目数据目录。工作目录在其中任何一个之内就拒绝；它们在工作目录之内时，文件工具把它们当作不存在（读、列、搜、写都拒绝，和 D-029 的密钥目录一样处理），沙盒用空目录盖住。为此 `FileAccess`、文件服务和沙盒服务新增 `--deny` 参数。
4. **自由度**：拒绝名单之外都可选；非系统盘的磁盘根（如 `D:\`）允许，系统盘根仍拒绝；系统 TEMP 目录之下的子目录允许（评测要用），TEMP 本身和 `AppData` 的其他部分仍拒绝。`WORKSPACE_ALLOWED_ROOTS` 只在配置时生效。
5. **拖拽文件**（回答 2）：只收文本文件（UTF-8，不含空字节，单个最多 1,000,000 字符，一条消息最多 5 个）。网页把文件读成文本后上传到 `POST /api/sessions/{id}/attachments`，存进会话归档（新的 `upload` 类，复用 `read_context_artifact` 工具读取）；消息带上返回的引用，服务在任务的固定上下文里列出附件名和引用，提示模型用这个工具读。需要对话归档；没有归档时接口返回 `attachments_unavailable`。图片和二进制文件以后再说。
6. **工作树**（回答 7）：在 `.claude/worktrees/workspace-choice`（分支 `exp/workspace-choice`）里实现和提交；验证通过、用户同意后再并入 `main`。

## 11. 实现与方案的差别（2026-11-10）

- 目录按钮放在输入框下面的选项行（文件夹图标加目录名），不放在会话标题下面：新会话还没有标题时也能选，和其他逐条消息的选项在一起。
- 不选目录时用启动时的目录和启动时的工具服务，行为和以前完全一样；选了才按次启动新的工具服务。
- 选择功能开启后，网页的“写文件”开关可用，默认关；命令行 `/dir` 选的目录只有启动时给了 `--write-root` 才能写。
- 附件只收 UTF-8 文本（浏览器按 UTF-8 解码，出现替换字符就拒绝）；GBK 编码的文件暂时不行。附件存在会话归档里（`upload` 类），模型用 `read_context_artifact` 读，任务的固定上下文只列文件名、引用和长度，不放内容。
- 目录变化的提示只写“目录已更换”，不写路径；审计记录头写入本次的工作目录（本机路径，只留在本机归档里）。
- `WORKSPACE_CHOICE=false` 可以整体关掉选择功能。
