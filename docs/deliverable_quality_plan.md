### 1.2 诊断字段 `answer_is_code_only` 有误判

`business_days` 的答案是纯代码，严格判定通过，但报告里 `answer_is_code_only` 是 `false`。

原因是 `bench/graders.py` 的 `extract_code`：没有代码块时，它从第一个以 `import`、`from`、`class`、`def` 或 `@` 开头的行开始截取，于是把文件开头的模块级常量（`_MONTH_LENGTHS = ...`）丢掉了，截出来的和原答案不相等。

这只影响诊断，不影响 `passed`。但以后看报告时，会误以为答案里混了说明文字。

### 1.3 `todo_html` 的 `enter_key_and_trim` 经常失败，而且可能是误判

这是调参集里最常见的失败：单一循环 10/11 的几次、团队的几次，都错在这一项。

- 规格写的是“点击‘添加’或在输入框按 Enter 都能新增一条待办；输入去掉首尾空格后为空时不添加”。
- 检查是纯文本匹配：页面里必须出现 `'Enter'`、`"Enter"` 或 `keyCode === 13`，并且出现 `.trim()`。
- 能满足规格却通不过检查的写法：
  - 把输入框放进 `<form>`，监听 `submit`（按 Enter 由浏览器提交表单，是很常见的正确做法）；
  - 用 `` `Enter` ``（反引号）或 `e.code` 判断；
  - 用正则去空白。
- 这几次的答案都没保留，所以现在**分不清**是智能体真没做到，还是检查太死。

`todo_html` 在调参集里，可以照它的失败改（D-035 只禁止照留出集改）。

### 1.4 `side_effects_qa` 的 `mutates_arguments`：期望答案本身有争议

这是留出集唯一一直答错的题（D-077 记为“历来都错”）。智能体每次都把 `remember` 列进“会修改调用者传入的参数对象的函数”，期望答案没有它。

```python
def remember(item, history=[]):
    history.append(item["sku"])
    return list(history)
```

- 题目说“不含只修改默认参数值的情况”。出题时的意思是：`remember` 修改的是默认参数值，所以不算。
- 但调用者完全可以传入自己的 `history`（`remember(item, my_list)`），这时它修改的就是调用者传入的对象。按题目前半句，“会修改”是成立的。
- 也就是说，智能体的答案可以说是对的；“只修改默认参数值”对 `remember` 并不成立。这是题目的问题，不是智能体的问题。

注意 D-035：留出集不能照智能体的失败去改提示或规则。**修正评测题本身的错误不算调参**，但会让这项检查和以前的结果不可直接比较，所以要你决定。这里只看了这道题的题面、期望和那次答案，没有据此改动智能体的任何东西。
