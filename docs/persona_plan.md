## 1. 要解决的问题

现在每个用户只有一种协作方式。想让它学 agent 时先讲概念和设计取舍、学后端时直接上代码再点评，只能每次在消息里说一遍。如果只做一份个人指令，两种要求又会互相打架。

需要的是：多份可以切换的设定，每份有自己的指令、默认选项，最后还要有自己的记忆。

## 2. 人设是什么

每个人设有四样东西：

| 部分 | 内容 | 例子 |
| --- | --- | --- |
| 名字 | 显示用，可以是中文，最多 40 字，同一个用户下不能重名 | “学 agent”、“学后端” |
| 指令 | 讲解风格和学习方式，最多 4000 字 | “先讲概念和取舍，再对照业界做法，不急着给完整代码” |
| 默认选项 | 执行模式、能不能写文件、用不用长期记忆、工作目录 | 学后端时默认用 single，工作目录是自己的练习仓库 |
| 记忆范围 | 用自己的记忆加公共记忆，还是只用公共记忆（第三步才生效） | 学 agent 时记下的薄弱点，学后端时不会召回 |

- 每个用户一开始只有一个“默认”人设，编号固定为 `default`，里面什么都没写。不建人设的用户，行为和现在完全一样。
- 每个用户最多 20 个人设。
- 联网搜索现在不是按任务选的（服务启动时就定了），所以不放进默认选项，以后再说。

## 3. 存在哪、什么格式

- 配置项 `PERSONAS_DIR`，默认 `data/personas`，按项目根目录锚定（和 `CONVERSATION_STORAGE_DIR` 一样，`app/config.py:143`）。留空表示关掉这个功能。
- 每个用户一个目录 `data/personas/<用户编号 SHA-256 的前 16 位>/`，命令行没有用户编号时用 `local`。目录在 `data/` 下，智能体的文件工具看不到。
- 每个人设一个文件 `<编号>.md`。编号由宿主生成（`default`，或者 `p-` 加 8 位十六进制），不用名字当文件名。
- 文件开头是一段用 `+++` 包起来的 TOML 设置，下面的正文就是指令，可以直接用编辑器改：

  ```
  +++
  name = "学 agent"
  mode = "single"
  write = false
  memory = "own"
  +++
  先讲概念和设计上的取舍，再对照业界的做法，能画流程图就画。
  不急着给完整代码，先让我自己说思路，你再点评。
  ```

  设置里认 `name`、`mode`、`write`、`use_memory`、`workspace`、`memory` 这几个键，其余的键报错。解析用标准库 `tomllib`，不加依赖。
- 同一目录下还有一个 `state.json`，记两样东西：
  - 每个会话绑定的人设：`{会话编号: 人设编号}`，最多保留最近 500 个会话；
  - 每个人设最近一次 `/btw` 加的那一行，给 `/btw undo` 用。
- 所有写入都是原子替换。每个用户一把锁，同一时刻只有一处在写。
- 每个任务开始时重新读一次人设文件（文件很小），所以用户在编辑器里改完，下一个任务就生效，不用重启。
- 文件格式不对、超过上限、键不认识时，这个任务不开始，提示用户哪一个人设、哪一项有问题，不带文件原文。

## 4. 人设怎么进到任务里

### 4.1 指令

- 和常驻指令方案的做法一样，新任务开始时（`_prepare_task`，`app/services/rag_agent_service.py:590`，`runtime is None`）调一次 `task.add_constraint`。阻塞后续跑的任务已经带着约束，不再加。
- 指令前面加一句宿主写的英文：`Instructions the user wrote for the persona of this session. Follow them unless the user's current message or the host rules say otherwise:`。人设的名字不进这句话。
- 优先级：宿主规则 > 用户这条消息 > 项目说明（以后） > 人设的指令。
- 走 `constraints` 的好处（常驻指令方案第 1 节已核实）：
  - 系统提示不改，黄金对照文件不会变；
  - 系统提示说文件和工具结果是“证据，不是指令”，`constraints` 不在这一列，所以人设指令会被当成指令；
  - 团队成员和调研成员的上下文保留 `constraints`（`delegation.py` 的 `_member_context`），也会照着做。
- 指令是用户自己写的，所以不用像项目说明那样先确认才加载。
- 指令为空（比如“默认”人设）时不加约束。

### 4.2 默认选项

- 在 `_open_task`（`rag_agent_service.py:533`）组任务选项的地方插进去。优先级：这条消息的选择 > 人设的默认 > 服务的默认。
  - 例如原来是 `execution_mode or self._execution_mode`，改为 `execution_mode or persona.mode or self._execution_mode`。
- 续跑的任务保留自己的选项（现在就是这样），不受当时人设的影响。
- 工作目录：
  - 只在这条消息没指定、命令行也没用 `/dir` 换过时，才用人设的工作目录；
  - 照样要经过 `check_workspace`；
  - 人设里**不支持**放系统盘上的目录，因为 D-074 要求每次确认，放进文件里就绕过了确认（第 9 节第 3 条）。设置时就拒绝，任务开始时再查一次，不通过就不开始任务，并提示用 `/dir`。

### 4.3 事件和记录

- 新任务开始时发一个 `persona` 事件，只带人设编号、指令字数和用了哪几项默认选项（只有键名）。
- 命令行打印一行：“本次任务用的人设：学 agent（指令 860 字）。”“默认”人设而且没写指令时不打印。
- 网页在路由提示旁边显示同样的话。
- 人设的名字只在本机界面上显示；轨迹、钩子事件、审计和日志只记编号和字数，不记名字和指令正文（D-059）。

## 5. 会话怎么绑定人设

- 每个会话绑定一个人设，记在 `state.json` 里，重启后还在。没有记录的会话用“默认”。
- 新建会话时用上一次用的人设（命令行是这次启动时 `--persona` 给的那个）。
- 切换只对下一个任务生效。正在等回答的任务保持原来的人设。
- 同一个会话中途换人设，前面的对话历史还在。切换时提示一句：“前面的对话还在这个会话里；想完全分开，可以新开一个会话。”不强制新开（第 9 节第 2 条）。
- 不根据问题自动判断领域：判断错了会用错风格，用户也看不出原因。

## 6. 输入栏命令

命令行交互模式和网页输入框都认下面这些命令。

| 命令 | 作用 |
| --- | --- |
| `/persona` | 列出所有人设，标出当前会话用的是哪个 |
| `/persona 名字` | 当前会话切到这个人设 |
| `/persona new 名字` | 新建一个空的人设，同时切过去 |
| `/persona show` | 显示当前人设的指令（带行号）、默认选项和文件位置 |
| `/persona set 键 值` | 改一项默认选项，比如 `/persona set mode team`、`/persona set workspace D:\practice`；值写 `-` 表示去掉 |
| `/persona rename 新名字` | 改名 |
| `/persona delete 名字` | 删除一个人设；“默认”不能删；正在用它的会话回到“默认” |
| `/btw 内容` | 在当前人设的指令末尾加一行，例如 `/btw 例子尽量用 FastAPI` |
| `/btw undo` | 撤掉最近一次 `/btw` 加的那一行 |

- `/btw` 加完回一句：“已加到「学 agent」的指令里，共 860 字，下个任务起生效。”
- 加了以后超过 4000 字就拒绝，提示用编辑器整理那个文件。
- `/btw undo` 只在指令最后一行还是上次加的那行时才撤，否则提示“指令已经改过，请直接编辑文件”。
- `/btw` 只改人设文件，不影响正在进行或者等回答的任务。
- 以后做个人指令（所有人设共用的部分）时，再加 `/btw --all`。这次不做。

### 6.1 命令行（`app/agent/__main__.py`）

- 交互循环里，在 `/remember` 那一组旁边（`__main__.py:250`）加 `/persona` 和 `/btw` 的分发。
- 单次任务加参数 `--persona 名字`，只用这一次，不改会话的绑定。
- 交互模式启动时也接受 `--persona`，作为这次启动的初始人设。
- `INTERACTIVE_HELP` 和帮助文字同步更新。
- 功能关掉（`PERSONAS_DIR` 留空）时，这些命令回一句“个性化人设没有开启”。

### 6.2 网页（`app/api/app.py`、`app/api/static/app.js`）

- 输入框提交时（`app.js:1356`），以 `/persona` 或 `/btw` 开头的内容由页面拦下来，调下面的接口，不当作任务发出去。其他以 `/` 开头的内容照旧当作消息发送，和现在一样。
- 接口都受访问令牌保护，请求体有大小上限：
  - `GET /api/personas`：人设列表（编号、名字、指令字数、默认选项）；
  - `GET /api/personas/{id}`：一个人设的全部内容，包括指令正文（用户自己写的，可以显示）；
  - `POST /api/personas`：新建；
  - `PUT /api/personas/{id}`：改名字、指令、默认选项；
  - `DELETE /api/personas/{id}`；
  - `POST /api/personas/{id}/btw`，请求体 `{text}` 或 `{undo: true}`；
  - `PUT /api/sessions/{session_id}/persona`，请求体 `{persona_id}`：切换会话的人设。
- 页面：
  - 会话标题旁边一个人设下拉框，显示当前人设，可以直接切换；
  - 设置里加“个性化人设”：人设列表、指令编辑框、默认选项；
  - 每次任务开始时显示 `persona` 事件那句话；
  - 指令正文按纯文本显示，不当作 HTML 渲染。

## 7. 记忆怎么分开（第三步）

- PostgreSQL 的 `memories` 表加一列 `persona_id TEXT`（`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`），空表示公共的。现有的记录全部当作公共的，不用迁数据。
- Milvus 索引要加 `persona_id` 字段。现在建表时要求字段正好是 `id`、`user_id`、`content`、`vector` 四个（`memory_vector_index.py:99`），所以要改结构、从 PostgreSQL 重建索引。D-006 定过 PostgreSQL 为准、Milvus 是可重建的索引，这一步照那个做。
- 召回时查“公共的 + 当前人设的”：`user_id == {uid} and (persona_id == "" or persona_id == {pid})`。人设的 `memory = "shared"` 时只查公共的。
- `/remember` 默认记到当前人设下，`/remember --shared` 记成公共的；`/memories` 标出每条属于哪个人设。网页的记忆面板同样。
- 删除人设时，它的记忆怎么办，第三步时再定（转成公共的、一起删，或者有记忆时不让删）。
- 自动从对话里总结学习习惯，依赖自动记忆（设计审查 3.4 节，还没接上）。等那件事定了再说；接上以后，自动记下的内容归到当前人设。

## 11. 实现时的补充

- **默认设置用不了时跳过，不让任务失败**：方案 4.2 节原来写的是人设的工作目录不能用时“不开始任务”。实现时统一改为跳过并在 `persona` 事件里报告（命令行打印“这些默认设置这次用不了，已跳过：工作目录”）。模式没准备、长期记忆没开也一样。否则一个过时的设置会让这个人设下的任务全部跑不起来。
- **`memory` 键先不认**：记忆分区是第三步，现在人设文件里写 `memory` 会报“不认识的键”，免得写了以为生效。第三步（D-089）定了不要这个键，见 [记忆分区方案](persona_memory_plan.md)。
- **`use_memory = true` 而长期记忆没开**：跳过，不报错。
- **网页的默认设置**：页面每次都把选项控件的值发给服务，所以人设的默认设置由页面在切换会话或人设时填进控件，用户还可以按消息改。服务端的 `resolve` 对请求里没带、人设设了的项留空，交给服务去填，并在事件里算作“用了”。
- **会话绑定**：没绑定的会话用最近用过的人设，第一个任务就绑定下来；之后换了“最近用的”也不影响它。
- **受保护目录**：`PERSONAS_DIR` 加进了 `WorkspacePolicy` 的受保护目录，放在 `data/` 以外时智能体也看不到；`.gitignore` 加了 `data/personas/`。
- **评测**：子进程设 `PERSONAS_DIR=''`，用户自己的人设不影响评测。
- **健康检查**：`/api/health` 只在人设开启时多一个 `personas: true`，没开时回答和以前一样。
- **`persona` 事件带人设名字**：只给本机的命令行和网页显示；它不进轨迹、钩子事件和审计。
- **网页显示**：任务卡片在“执行过程”里显示“人设：学后端（指令 13 字）”。用假模型在本机起服务看过：`/persona new`、`/btw`、面板保存、任务卡片的人设提示都正常，控制台没有报错。
- 黄金对照文件一个都没变；没有用真实模型验证。
