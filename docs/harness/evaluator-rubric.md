# Evaluator Rubric

课程模板：6 个维度，每个 0–2 分；结论为 Accept / Revise / Block。评审时必须引用可复现的证据（命令、文件、行号），不能只凭印象打分。

| 维度 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Correctness 正确性 | 行为错误，或无法判断 | 主路径正确，边界情况未覆盖 | 用户要求的每一项都有对应实现，边界已处理 |
| Verification 验证 | 没有验证，或零测试被当成通过 | 只有 static/import 或局部验证 | 运行了适用级别的验证（确定性测试 / 真实服务 / E2E），失败也记录在案 |
| Scope discipline 范围 | 改了范围外的文件或配置 | 有小幅越界但已说明 | 只改约定的文件，保留用户原有差异 |
| Reliability 可靠性 | 破坏取消/超时/版本/预算等不变量 | 不变量未受影响，但没有验证 | 不变量有测试或证据支撑 |
| Maintainability 可维护性 | 新增重复框架或难懂的结构 | 可读，但与现有模式不一致 | 复用现有扩展点，命名和结构一致 |
| Handoff readiness 交接 | 状态文件没有更新 | 部分更新 | progress / handoff / feature_list / DECISIONS 齐全，clean-state 清单已勾选 |

结论规则：

- **Block**：Verification、Scope 或 Reliability 任一项为 0。
- **Accept**：总分 ≥ 10，且没有任何 0 分。
- **Revise**：其余情况。

校准方法：拿已完成的任务打分并与人工判断对比；对有分歧的维度收紧描述；重复 3–5 轮，分歧记录在本文件末尾。
