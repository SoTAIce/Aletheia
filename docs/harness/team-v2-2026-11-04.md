## 行为要点

- **完成由宿主判定**：开启沙盒时，执行者报告成功，并且最后一次写文件之后有通过的运行，团队立即完成，不再调用负责人。开启审查时，还需要在最后一次写文件之后得到批准。
- **负责人自己给出的最终回答**：不满足条件时退回一次，再不满足就以 `TeamError` 结束。`FAILED:` 开头的回答直接结束，`BLOCKED:` 开头的回答返回阻塞结果并附上问题。
- **执行者失败**（参数修复用完、轮数超限等）：只把异常类型名报告给负责人，由它重新委派，总次数受 `max_delegations`（默认 6）限制。如果失败的执行者有写入权限，它可能已经写过文件，所以门槛视为“有未知写入”，必须重新跑通过。
- **权限**：只授予白名单里、而且父级注册表中存在的工具；审查者永远拿不到写入和运行工具。授权不合法时，宿主直接回复负责人，不运行成员，也不计入委派次数。
- **上限**：委派 6 次、负责人 16 轮、每个执行者 12 轮工具调用 / 24 次工具调用、团队时限（`--team-timeout`）。团队级失败都是 `TeamError`，不会被外层重新规划重复执行。
- **轨迹**：`Team trace:` 只含版本、状态、预算（模型调用、工具调用、委派、负责人轮数、秒数、写入次数）、每次委派的成员名、角色、工具名、状态、工具序列、是否满足门槛和异常类型名。失败或设置 `ALETHEIA_TEAM_TRACE=1` 时以 WARNING 输出。

## 第一次真实评测（用户 2026-11-04“授权 2 次”）

| 任务 | 状态 | 耗时 | 执行 | 失败 |
|---|---|---|---|---|

| fix_inventory | failed | 6.5 秒 | 0 | 同上 |

两次都**没有进入团队**。原因：V2 让外层规划器只产生 1 步（`max_steps=1`），但模型仍可能输出多步或超过 300 字符的步骤；规划器只修复 JSON 格式错误，不修复这类校验错误（`ValueError`），于是直接失败。评测器只认 `XxxError` 开头的失败信息，认不出 `Planning failed:` 开头的那一行。这是我在接入时没用端到端测试覆盖的衔接问题。

### 修复

- 新增 `SingleStepPlanner`（`team_v2.py`）：V2 下计划固定为一步，不调用规划模型；负责人自己读取 `active_goal`。服务里 V2 改用它。
- 评测器的失败识别允许 `Planning failed: ` 前缀（规划器校验信息是宿主撰写的）。
- 新增 3 项测试：固定单步规划不调用模型；评测器识别规划失败；**运行时端到端**（固定单步计划 + V2 运行器 + 沙盒门槛，一次执行完成）。
- 验证：`tests/test_team_v2.py` 22 passed；当前 tests 116 passed；完整历史 1090 passed（3 项已知失败不变）；init.ps1 PASS；输出文件、TEMP、`__pycache__` 已清理，无容器残留。

## 第二次真实评测（用户 2026-11-04“再授权 2 次”）

| 任务 | 状态 | 耗时 | 模型/工具调用 | 失败 |
|---|---|---|---|---|
| parse_duration | failed | 3.7 秒 | 1 / 0 | `StepModelError -> ModelRequestError -> BadRequestError`（负责人第一次调用） |
| fix_inventory | failed | 3.7 秒 | 1 / 0 | 同上 |

固定单步计划生效了，这次进入了团队；但负责人的第一次请求就被服务方拒绝（400）。原因：`.env` 的 `RAG_JSON_MODE=true` 让每个请求都带 `response_format: json_object`，服务方要求这种请求的消息里必须出现 “json” 一词。负责人的提示里没有这个词（普通模式和 V1 的提示里都有）。另外，JSON 模式下模型只能输出 JSON，原来设计的纯文本最终回答也行不通。

本地对比了负责人与普通模式实际发出的请求结构（不联网），除提示文字外没有差别。

### 修复

- 负责人的最终回答改为和普通模式相同的 JSON 结果：`{"status": "succeeded|failed|blocked", "content": ..., "reason": ...}`，提示里写明；纯文本加 `FAILED:` / `BLOCKED:` 前缀仍作为兜底。
- 新增 5 项测试：负责人的每个请求都含 “json”；JSON 的成功、阻塞、带代码块的结果；JSON 的失败结束团队。
- 验证：`tests/test_team_v2.py` 28 passed；当前 tests 122 passed；完整历史 1090 passed（3 项已知失败不变）；init.ps1 PASS；输出文件、TEMP、`__pycache__` 已清理，无容器残留。

- **fix_inventory**：一次委派完成。执行者读文件 → 写两次 → `run_tests` 通过，宿主随即判定完成，负责人只用了 1 轮。
