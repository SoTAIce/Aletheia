# 网页后端与前端接入设计稿

日期：2026-11-06。状态：**已确认，实施中**。来源：用户 2026-11-06“先写设计稿”；第 11 节四个问题用户 2026-11-06 答“都按推荐”。

## 1. 目标和范围

让智能体能在浏览器里使用：发消息、看到每一步的进度、任务停下来时回答问题并接着做、中途取消、管理长期记忆。

第一版只做到：

- 本机使用，一个进程，一个用户（或少数几个固定用户）。
- 一层薄后端，把现有的 `RagAgentService` 包成网络接口，智能体核心只加一个进度回调。
- 一个不需要构建工具的静态网页。

第一版不做：公网部署、注册和登录系统、多进程或多机扩展、团队模式的专门界面、知识库管理界面。

## 2. 现在能直接用的部分

| 已有能力 | 位置 | 对后端的意义 |
| --- | --- | --- |
| 一次请求跑一个任务，返回 `AgentRunResult`（`task_id`、`status`、`content`、`usage`、`step_log`、`failure_kind`） | `app/services/rag_agent_service.py` 的 `query_result` | 后端的核心调用，不用改 |
| 按 `user_id` 和 `session_id` 区分对话，同一会话的请求串行 | 同上，`_session_key` 和 `_locks` | 会话隔离已经有了 |
| `request_id` 幂等：同一个编号重复提交会返回已存的结果，不会重新执行 | 同上 | 网络重试是安全的 |
| 任务停下后用 `resume_task_id` 和 `question_id` 接着做 | 同上；交互命令行已用真实模型跑通（e2e-live-001） | 阻塞和恢复的接口已经定好 |
| 失败时的中文说明 `user_message` | `app/agent/runtime.py` 的 `FAILURE_MESSAGES` | 网页直接显示 |
| 每一步的宿主记录：步骤号、结果、耗时、调用了哪些工具、是否成功 | `AgentRuntime._log_step` 写入 `step_log` | 进度事件的数据来源 |
| 长期记忆的写入、列出、删除 | `remember_explicit`、`list_memories`、`forget` | 记忆面板直接调用 |
| 对话归档，可按会话读回历史 | `ConversationArchive.load_turns` | 历史记录接口的数据来源 |
| `fastapi==0.128.8`、`uvicorn[standard]==0.40.0`、`httpx` | `pyproject.toml`，已安装在 `.venv` | **不需要新增依赖** |

## 3. 现在缺的部分

1. **没有进度**：`query_result` 只在任务结束时返回一次；`query_stream` 名为流式，其实也只发最终结果。一个任务通常要跑几十秒，网页不能干等着。
2. **停下的任务只在内存里**：等待回答的任务存在 `self._tasks` 里，进程重启后就没了，只能看到历史，不能接着做。
3. **没有取消接口**：取消协程时服务会把这一轮标为“已取消”，但外部没有入口。
4. **身份只是一个参数**：`user_id` 谁都能填，接到网络上必须由后端决定，不能由浏览器传。
5. **报错会带原始异常**：`query_stream` 把 `f"{type(exc).__name__}: {exc}"` 直接发出去，违反“不记录不受控异常”的约束，后端不能沿用这个方法。
6. **没有会话列表和历史读取**：归档能按会话读回，但服务上没有对应的方法。

## 4. 总体结构

```
浏览器（静态页面）
   │  HTTP + 服务器推送事件（SSE）
   ▼
app/api/            新增：FastAPI 应用、路由、运行管理、事件缓冲
   │  直接调用
   ▼
RagAgentService     现有：一个进程只建一个，在应用启动时创建、关闭时释放
   │
   ▼
AgentRuntime 等     现有：只加一个可选的进度回调
```

关键设计：**一次运行和一次 HTTP 请求分开**。提交消息时，后端为这一轮开一个后台协程（称为“运行”）并立刻返回运行编号；浏览器再用这个编号订阅进度事件。这样：

- 刷新页面或断网重连不会打断任务，重新订阅就能接着看。
- 关闭页面默认**不取消**任务（任务可能正在写文件，半途停下更难收拾）；取消必须明确点按钮。
- 运行结束后，结果仍按现有逻辑写进对话归档。

## 5. 接口

所有接口都在 `/api` 下，请求和响应都是 JSON（事件流除外）。`user_id` 一律由后端根据身份决定，请求里不接受这个字段。

### 5.1 会话和消息

| 方法和路径 | 作用 | 说明 |
| --- | --- | --- |
| `GET /api/sessions` | 列出当前用户的会话 | 需要在服务上加一个只读方法，从归档目录列出 |
| `GET /api/sessions/{session_id}/turns?limit=20` | 读回历史 | 返回每一轮的用户消息、回复、状态、时间；不返回工具原始输出 |
| `POST /api/sessions/{session_id}/messages` | 发一条消息，开始一次运行 | 见下 |

发消息的请求体：

```json
{
  "content": "帮我把这句话翻译成英文",
  "request_id": "浏览器生成的唯一编号",
  "resume_task_id": null,
  "question_id": null
}
```

- `request_id` 必填，由浏览器生成。重复提交同一个编号：运行还在跑就返回同一个运行；已经结束就返回已存结果（沿用服务现有的幂等逻辑）。
- 上一轮停下来等回答时，浏览器把那一轮的 `task_id` 填进 `resume_task_id`。`question_id` 只在一个任务同时有多个待回答问题时才需要。
- 成功返回 `202`：`{"run_id": "...", "events": "/api/runs/{run_id}/events"}`。`run_id` 就用 `request_id`，不再另起编号。

错误码：

| 情况 | 状态码 | 返回的 `code` |
| --- | --- | --- |
| 内容为空或过长、编号格式不对 | 400 | `invalid_input` |
| 同一会话已有运行在跑 | 409 | `session_busy` |
| 要恢复的任务不存在（例如进程重启过） | 409 | `task_not_resumable` |
| 同一个 `request_id` 配了不同内容 | 409 | `request_conflict` |
| 全局同时运行数已满 | 429 | `too_many_runs` |
| 未通过身份验证 | 401 | `unauthorized` |

所有错误都返回 `{"code": "...", "message": "中文说明"}`，**不带异常原文**。服务里已有的 `ValueError` 按消息内容映射到上面的代码；映射不到的一律是 500 `internal_error`，原始异常只写进本地日志的异常类型名。

同一会话正在运行时直接拒绝，而不是排队：服务本来就按会话串行，排队会让浏览器看不出自己的消息在等什么，拒绝更清楚。

### 5.2 运行和进度

| 方法和路径 | 作用 |
| --- | --- |
| `GET /api/runs/{run_id}` | 运行的当前快照：状态、已有事件数、最终结果（结束后） |
| `GET /api/runs/{run_id}/events` | 服务器推送事件（SSE）。支持 `Last-Event-ID`，断线重连从断点续发 |
| `POST /api/runs/{run_id}/cancel` | 取消运行 |

事件类型（每个事件都带递增的 `id`）：

| 事件 | 内容 | 来源 |
| --- | --- | --- |
| `accepted` | `run_id`、`session_id` | 后端，运行开始时 |
| `route` | 选了普通还是团队模式、是否只读 | 已有的路由选择记录 |
| `plan` | 计划修订号、步骤数、每一步的标题 | 运行时安装计划时 |
| `step` | 步骤号、结果（成功、失败、阻塞、超时）、耗时、工具名和是否成功 | `_log_step` 写入的那条记录 |
| `blocked` | `task_id`、要问用户的问题（`question`） | 运行结果 |
| `completed` | 最终回复、用量（模型调用次数、令牌、秒数） | 运行结果 |
| `failed` | `failure_kind`、中文说明 `user_message` | 运行结果 |
| `cancelled` | 提示“工具可能已经产生了副作用” | 取消时 |

事件里只放宿主自己写的记录，**不放工具原始输出、模型原文或异常原文**，与现有日志的约束一致。最终回复本来就是给用户看的，照常发送。

事件缓冲：每次运行在内存里保留全部事件，结束后再保留一段时间（默认 30 分钟，可配置）供重连读取，过期就删。历史以对话归档为准，不另存事件。

### 5.3 长期记忆

只在配置了 `LONGTERM_MEMORY_DSN` 时提供，否则返回 404 `memory_disabled`。

| 方法和路径 | 作用 | 对应的已有方法 |
| --- | --- | --- |
| `GET /api/memories` | 列出当前用户的记忆 | `list_memories` |
| `POST /api/memories` | 记住一条：`{"content": "..."}` | `remember_explicit` |
| `DELETE /api/memories/{memory_id}` | 删除一条 | `forget` |

### 5.4 其他

- `GET /api/health`：进程是否正常、长期记忆是否可用、当前运行数。不返回配置值和密钥。
- `GET /`：返回静态页面。

## 6. 智能体核心需要的改动

只有两处，其余都在新增的 `app/api/` 里：

1. **进度回调**：`AgentRuntime` 增加一个可选参数 `on_event`，在安装计划和记录步骤时调用，传入的就是现在写进日志和 `step_log` 的那份记录。回调出错只记一条警告，不影响任务。`RagAgentService.query_result` 增加同名可选参数并原样传下去。不传时行为完全不变，现有测试不受影响。
2. **会话列表和历史读取**：服务上加两个只读方法，从归档读回。只返回给用户看的字段。

`query_stream` 保持不动，后端不使用它。

## 7. 并发、取消和资源

- **同一会话**：一次只允许一个运行（见 5.1）。
- **全局上限**：同时运行数默认 2，可配置。每个运行都会调用真实模型、启动一组工具服务进程，上限主要是为了控制费用和本机负载。
- **长期记忆**：向量索引的类级锁 `MemoryVectorIndex._lock` 在工作线程里使用，不会卡住事件循环，但会让各会话的记忆读写排队。第一版的规模下可以接受，记录为已知限制。
- **取消**：取消对应的后台协程。服务已有处理：这一轮标为“已取消”，任务标为失败，内容提示工具可能已有副作用。取消后这个任务不能再恢复。
- **进程关闭**：先停止接受新消息，等运行结束（有时限，默认 30 秒），超时的运行按取消处理，最后关闭服务。
- **重启后停下的任务**：第一版不保留，接着回答会得到 `task_not_resumable`，网页提示用户重新提问。是否要保留见第 11 节。

## 8. 身份和安全

第一版只在本机使用：

- 默认只监听 `127.0.0.1`。
- 身份用一个访问令牌：启动时从环境变量读取，浏览器在请求头里带上。令牌对应的用户编号由配置决定，默认 `local`，与交互命令行一致。没有设置令牌时拒绝启动，除非显式声明“只在本机、无需令牌”。
- 不开跨域：页面由同一个服务提供，同源访问即可。
- 消息长度、`request_id` 长度都设上限，沿用服务现有的校验。
- **写文件和沙盒运行默认关闭**，和命令行一样必须显式配置写入目录才开启。网页上要明确显示当前是否允许写文件。
- 响应、事件、日志里都不出现密钥、配置值、异常原文和工具原始输出。

## 10. 前端第一版

一个静态页面，由后端直接提供，不引入构建工具，也不需要安装任何前端依赖：

- 左侧：会话列表，新建会话。
- 中间：对话记录；运行中的那一轮下面显示计划和逐步进度（步骤号、结果、耗时、用了哪些工具）；有取消按钮。
- 停下等回答时：问题突出显示，输入框提示“回答上面的问题”，发送时自动带上 `resume_task_id`。
- 失败时显示中文说明。
- 右侧（开启长期记忆时）：记忆列表，可添加和删除。
- 顶部：当前是否允许写文件、长期记忆是否可用。

以后如果需要更复杂的界面，再换成有构建步骤的前端框架，接口不变。

## 14. 实现时的调整（D-046）

- 不开跨域，页面和接口同源。
- 浏览器自带的 `EventSource` 不能带请求头，前端用 `fetch` 读事件流，这样令牌仍放在请求头里，不进地址栏。
- `blocked` 事件不带 `question_id`。一个任务只有一个待回答问题时，服务会自动选中；有多个时返回 `400 question_required`。
- `GET /` 返回页面，`/static/app.js`、`/static/app.css` 是仅有的两个页面文件（D-047）。自动生成的接口文档页面已关闭，响应头不带服务器名。
- 重复提交同一个 `request_id`：运行还在内存里时返回 `200` 和同一个运行（`created: false`），新建时返回 `202`。

## 15. 风险

- 后台运行和 HTTP 请求分开后，进程内会同时存在多个运行，资源泄漏（工具服务进程没关）会比命令行更明显。关闭流程和测试要覆盖到。
- 事件缓冲在内存里，运行很多时占用会涨；靠保留时限和全局上限控制。
- 网页上的提问和恢复依赖 D-043 的提示约束，仍然可能出现模型没写成问句的情况；网页照常显示，不另做改写。
