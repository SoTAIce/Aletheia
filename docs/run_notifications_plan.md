## 1. 要解决什么

一个任务最长可能跑 8 分钟（单一循环 480 秒），用户会切到别的标签页或窗口去做别的事。现在任务完成、停下来问问题、或者等你确认写文件时，网页都没有任何动静，只能隔一会儿切回来看。等待确认时，任务一直卡着不动。

## 2. 现状

- 网页用事件流跟踪正在跑的那个任务（`app/api/static/app.js` 的 `follow`，读 `/api/runs/{id}/events`）。`LiveView.show` 处理每个事件：`approval_required` 弹确认卡片，`completed`、`blocked`、`failed`、`cancelled` 结束这次运行（`finish`）。
- 只跟踪**当前打开的会话**的运行：切到别的会话时 `openSession` 把 `state.run` 设为空，跟踪停止；切回来时从 `aletheia-runs` 里接着跟（`resumeFollowing`）。
- 定时任务（D-102）在后端自己跑，网页不跟踪。
- 页面的安全策略（`app/api/app.py:35`）不影响浏览器通知接口。浏览器只在“安全来源”上提供通知：`127.0.0.1`、`localhost` 算安全来源，局域网里用 `http://` 打开的地址不算，在那种地址上通知接口不可用。

## 3. 设计

### 3.1 什么时候通知（第 7 节第 1 问）

只在**页面不在前台**时（`document.hidden` 为真，即切到了别的标签页、最小化了窗口）通知；你正看着页面时不打扰。

| 事件 | 通知文字（标题都是 “Aletheia”） |
|---|---|
| `completed` | 任务完成 |
| `blocked` | 任务停下来等你回答一个问题 |
| `failed` | 任务失败 |
| `approval_required` | 有一步操作等你确认 |
| `cancelled` | 不通知（是你自己取消的） |

- 文字全部由前端写死，**不带任何模型写的内容**：不带答案、不带追问的问题、不带确认卡片里的路径和预览，也不带会话名（会话名来自你的第一条消息）。通知会出现在系统通知中心和锁屏上，原文不该出现在那里（D-059 的精神）。
- 每次运行用同一个通知标签（`tag` 设为运行编号），新通知替换旧的，不会堆一串。
- 点击通知：把窗口切到前台（`window.focus()`），关掉这条通知。
- 回到页面时，把这次运行还没关的通知关掉。

### 3.2 怎么打开（第 7 节第 2 问）

- 浏览器要求在用户点击时才能请求通知权限，所以顶部状态栏加一个开关按钮“通知”，放在“记忆”等按钮旁边。
- 第一次点：请求权限。允许后开关变成“开”；拒绝后提示“浏览器拒绝了通知，可以在浏览器的网站设置里重新允许”。
- 开关状态只存在这个浏览器里（`localStorage` 的 `aletheia-notify`），默认**关**。
- 通知接口不可用时（不是安全来源，或浏览器不支持），按钮不显示通知选项，只保留 3.3 的标题提示，悬停说明“这个地址不能用浏览器通知，可以用 127.0.0.1 打开”。

### 3.3 标签页标题提示（第 7 节第 3 问）

- 不管通知开没开，页面不在前台时，同样四种事件把标签页标题改成 `（完成）Aletheia`、`（等你回答）Aletheia`、`（失败）Aletheia`、`（等你确认）Aletheia`。
- 回到页面就恢复成 `Aletheia`。
- 这样即使不开通知、或者地址不能用通知，在标签栏上也能看到。

### 3.4 范围（第 7 节第 4 问）

- 只覆盖**这个标签页正在跟踪的运行**，也就是当前会话的。切到别的会话后，原来那个会话的运行不会通知。要覆盖所有会话，得同时跟多条事件流，改动大，这次不做。
- 定时任务不通知。
- 后端不改。

### 3.5 要改的文件

- `app/api/static/app.js`：开关、权限请求、`notifyRun(kind, runId)`（判断前台、开关、权限，发通知或只改标题）、`visibilitychange` 时恢复标题、关通知；在 `LiveView.show` 的 `approval_required` 和 `finish` 里调用。
- `app/api/static/index.html`：状态栏加按钮。
- `app/api/static/app.css`：按钮开关状态的样式，照现有的 `link-btn` 和 `.on`。
- 新增 `tests/test_run_notifications.py`：静态检查（见第 4 节）。
- 不改：后端、事件格式、安全策略头、依赖。

## 4. 测试

仓库没有前端运行时测试，只有对静态文件的文本检查（`tests/test_web_api.py` 第 334–348 行那种）。这次照这个写法：

- 静态检查：`app.js` 里只有四段通知文字，`new Notification(` 的参数里不出现 `event.content`、`event.question`、`event.message`、预览或会话名之类的字段；请求权限只在按钮的点击处理里；默认关。
- 手动验证（需要你在浏览器里点一下允许）：本机 `python -m app.api` 打开 `127.0.0.1`，发一个要跑一会儿的任务，切到别的标签页，看完成、确认、追问三种通知和标题；回到页面后标题恢复。这一步要调用真实主模型，大约几千到两万令牌，需要你同意；也可以只做离线检查，手动验证留给你自己用的时候顺便看。
- 我可以用内置浏览器检查按钮、标题切换和不可用时的提示，但内置浏览器里的通知权限和系统通知不一定和你平时的浏览器一样。

## 5. 不做的

- 声音提示、手机推送、邮件。
- 覆盖其他会话和定时任务（见 3.4）。
- 通知里带答案摘要或会话名。

## 6. 风险

- 浏览器、系统的“专注模式”可能把通知静音，这不归网页管。
- 局域网 `http://` 地址用不了通知，只有标题提示。
- 只看当前会话：开了两个会话各跑一个任务时，只有正在看的那个会通知。
